# 07. AI Features

AI is where KubeiQ must lead. The reference has AI log analysis and a cluster chat; we already
have deeper diagnosis (Cluster Doctor: detectors first, then a tool-calling agent, ADR 0005) and
the Explain chat per incident. The work is to bring that intelligence into every view.

## Today

- Cluster Doctor investigations with structured diagnoses, fix commands and confidence.
- Ask KubeiQ: follow-up questions per incident, with live read-only checks.
- One AI model through LiteLLM (ADR 0004); redaction before anything reaches a model.

## Requirements

### Log analysis

- **MUST** add **Analyze** to the log drawer (05): a split view, logs on one side and the analysis on
  the other.
- **MUST** return a structured, schema-validated result: summary, status, errors (line, meaning,
  severity, clickable to jump to the line), root cause, fix steps with complete commands
  (`detectors/commands.py` rules), what to watch next.
- **MUST** send bounded, redacted logs (the last N lines and the error neighbourhood, never the full
  stream) and the pod's context (status, restarts, recent events), so the answer is about this pod.
- **MUST** allow follow-up questions in the same panel, with the same read-only tools as Ask KubeiQ.
- **SHOULD** offer "Investigate this workload" to open a full Cluster Doctor run.

### Cluster assistant

- **MUST** offer an assistant panel scoped to the cluster in scope: "why is checkout slow", "which
  pods restarted today", "what changed in payments".
- **MUST** use our tool-calling agent with read-only tools (`agent/tools.py`), chosen by the model,
  not by keyword matching. Secrets stay hidden; tool output is redacted.
- **MUST** save conversations per user (list, rename, delete), with the cluster each belongs to.
- **MUST** cite what it looked at ("Read logs of payment-1", as Ask KubeiQ does) and give complete
  commands.
- **SHOULD** suggest starting points from the cluster's current problems.
- **MUST NOT** change the cluster. Suggested changes link to Cluster Manager, where ADR 0009 applies.

### Everywhere

- **SHOULD** add Explain to warning events (Timeline) and Investigate to failing rows and cards.
- **MUST** respect "AI is off": features hide behind a single notice with Add a Model.
- **SHOULD** support several providers with a default (03).

## Do better than the reference

- Tools chosen by the model with our agent loop, not by keywords; context built from evidence.
- Structured, validated output and complete fix commands, consistent with Cluster Doctor.
- Every answer grounded in live, redacted, bounded evidence.

## Tier

Core. Usage limits or team-wide conversation sharing MAY become paid later.

## Done when

- Analyze on each broken example (`examples/`) names the root cause the detectors find.
- No secret or token appears in any prompt (redaction tests).
- The assistant answers the questions above on the kind cluster using tools, with commands that run.
